## DSH 可视化面板

主导航为「首页」「功能」「任务」「表情包」「记忆」「设置」。「设置」内分为「QQ账号」「聊天对象」「模型服务」「声音」「性格」「手机」「安装与更新」。默认展示日常状态和操作；ⓘ 可悬停、聚焦或点击查看说明，版本、端点和诊断记录等技术信息收在「高级设置」。实际错误、待核实结果、费用及发送、录音、重启等操作后果仍在相关操作旁直接显示。「仅保存」保留设置；「保存并生效」会重新加载伴侣服务，QQ 连接可能短暂重建。

在 **设置 → 大肥鱼 → 功能** 查看电脑终端与文件、电脑界面、浏览器、网络搜索与读取、QQ、安卓手机、语音接收、语音发送、长期记忆、表情包和后台任务，共 11 项。页面、主人会话的只读工具 `dafeiyu_capabilities` 和大肥鱼的动态上下文读取同一份能力注册表。能力状态表示当前检测证据，实际操作仍遵守当前账号和工具授权。

打开页面、刷新状态或调用查询工具只读取快照，不会自动探测或执行操作。需要检查时，由主人点击「检查连接」；需要确认实际操作时，再点击该项的「试一下」发起安全验证。默认显示可用状态和操作，命令入口、技能、终端、系统权限及详细验证记录在「高级详情」中查看；缺少权限或结果未确认时仍给出直接提示。**“待检查”不等于没有能力**：大肥鱼应先查看当前可用工具，再依据真实调用结果判断，不能只因没有验证记录就声称不会。

“入口/权限已检测”仍不等于真实点击、输入已通过。验证证据默认有效 10 分钟；环境、权限或运行实例变化会撤销旧证据，重启后加载的历史记录也只作为过期证据展示。超时、取消或结果未确认不会自动重试或重放；需要核对后由主人重新明确发起验证。检测、验证与保存或应用配置互斥，普通聊天保持可用。

电脑和浏览器的安全验证仅使用验证自身创建的临时文件、本地页面或独立的原生测试窗口，不读取私人记忆、不发送 QQ 消息、不操作手机。桌面验证会临时打开一个空白测试窗，由真实 Orca 工具输入随机标记、点击确认并读回结果，然后关闭窗口并清理。QQ、手机、语音的真实收发与设备操作仍在各自专页按明确授权单独验收，不能从电脑验证结果推导通过。

在 macOS 上，主人实际要求读取 DSH 自身界面时，可使用 `dafeiyu_desktop_prepare` 请求初始化 Electron 辅助树，再交给 computer-use 操作。初始化及独立原生测试窗口需要已安装的系统命令行工具；模块不会自动安装软件或更改系统辅助功能授权。初始化请求被接受仍不代表操作成功。当前 Orca 对 DSH 自身窗口存在系统共享浮层匹配问题；若读不到目标，应停止操作。独立测试窗通过不能证明所有应用或 DSH 自身兼容。

## 先说个事

我给一个 AI 接上了 QQ 和一台安卓手机。

```
她自己去翻我的相册，挑了 5 张她觉得好看的存进自己的图库，
```

这些不是我写好的台词。**是她自己生成的。**

## 这两个东西解决什么问题

市面上的 AI 助手已经很强了，但它们有两个共同的短板：

**① 没有人味。** 回复"唰"一下全出来、一次说一大段、
不管你在群里闲聊还是在跟它说正事，它都用同一种客服腔。
而且它**不记得你**——今天说完，明天就忘。

**② 没有手。** 它能写代码、能查资料、能分析数据，
但它**碰不到你的手机**——开不了 App、点不了按钮、看不了屏幕。

这个仓库补上这两块：

| 缺什么 | 谁补 | 怎么补 |
|---|---|---|
| 记不住人 | `ai-companion/Memory` | 记忆按**人**存，不按会话存；跨场合共享一条对话流 |
| 不像人打字 | `ai-companion/Humanizer` | 打字时长、自动分条、条间停顿、深夜变慢 |
| 太吵 | `ai-companion/Waker` | @/名字/提问/拍一拍/关键词/概率，条件独立，可潜水 |
| 不像"她" | `ai-companion/Role` | 角色卡 + 体检，防止写成客服手册 |
| 只记事，不像过日子 | `ai-companion/Diary` | 日记单独存：按天翻、算"认识第几天"、只喂最近 3 条进上下文 |
| 碰不到手机 | `phone-mcp` | 34 个 MCP 工具，通过 adb 驱动真机或模拟器 |

## 快速开始

### 只要陪伴

```bash
cd packages/companion
cp config.example.json config.json     # 填 API key 和你的 QQ 号
cp role.example.md role.md             # 改成你想要的角色

npm run check     # 角色卡体检
node examples/demo.js    # 离线 demo，不需要 key
npm run dry       # 干跑：生成但不发送
npm start         # 真跑（需要一个 OneBot 实现，见包内 README）
```

> **这里最容易卡住的一步是 `npm start`。**
> 它需要一个 **OneBot 实现**（能连上 QQ 的网关程序）。
> 这一步没有一行命令能搞定 ✗ 见[完整教程](docs/完整教程-从零搭一只小鲸鱼.md)第三章 ✓

### 只要手机

```bash
cd packages/phone-mcp
npm install
node src/phone-mcp.js --selftest     # 自动探测 adb 和设备
```

然后在你常用的 MCP 客户端里配上它：

```json
{
  "mcpServers": {
    "phone": { "command": "npx", "args": ["-y", "phone-mcp"] }
  }
}
```

## 两个包怎么配合

它们**不互相依赖**，但拼在一起会很有意思：

```
        ┌──────────────────────────────────────────┐
        │  一个"住在你设备里"的 AI                   │
        └──────────────────────────────────────────┘
                            │
        ┌───────────────────┴───────────────────┐
        │                                       │
   ┌────▼─────────────────┐         ┌───────────▼────────────┐
   │  ai-companion        │         │  phone-mcp             │
   │                      │         │                        │
   │  记得住你             │         │  能开 App、点按钮       │
   │  打字像人             │◀───────▶│  能截图、能录屏         │
   │  知道该不该说话        │  一起用  │  能玩游戏、能刷视频      │
   └──────────────────────┘         └────────────────────────┘
```

例如：让它替你在手机上签到、刷视频、玩游戏，
同时它在 QQ 上还是那个记得你昨天熬夜、会催你早睡的熟人。

也可以只用一半：
- 只想给自己做个"会记住我的 QQ 机器人" → 只用 `companion`
- 只想让 AI 帮着点手机 → 只用 `phone-mcp`

## 设计原则

写这两个包的时候守了几条：

**1. 每一层都能单独用。**
不搞"必须整套上"的框架。只想要拟人化发送？`new Humanizer()` 就完事。

**2. 不绑定平台和模型。**
`companion` 只依赖 OpenAI 格式的接口；换平台只写一个 transport。
`phone-mcp` 只依赖 adb；换手机不用改代码。

**3. 数据都是纯文本。**
账本是 JSON，对话流是 JSONL。随时能打开看、能 grep、能手改、能备份。

**4. 不确定的事明确报错，不静默失败。**
没装 ADBKeyboard 就说"没装"，而不是默默把中文丢掉。

**5. 该闭嘴的时候闭嘴。**
一个不会看场合的机器人，比不会说话的更烦人。

## 注意

⚠️ **`phone-mcp` 给 AI 的是真手机的完整操作权。**
不要接到装着支付、银行 App 的主力机上；推荐用模拟器或备用机。
QQ 空间评论这类"发出去撤不回"的操作，项目里已内置限流，请保留。

⚠️ **`companion` 会把你和它的对话存在本地。**
数据不出本机（除了发给模型的那部分）。介意的话看一下 `data/` 目录。

⚠️ **腾讯对 QQ 机器人有风控。** 自动化频率过高会被限速甚至封号。
这个项目里的限流参数是**踩过坑之后调出来的**，别为了提高响应速度把它们调大。
