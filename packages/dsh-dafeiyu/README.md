# dsh-dafeiyu

大肥鱼的 DSH 原生适配层。官方 QQ 机器人和普通 QQ 小号是两个不同入口。官方 QQ 沿已安装的宿主 QQ 插件运行；普通 QQ 小号需已登录的 OneBot 网关，并通过本项目适配进入 DSH 原生 Agent。

2026-10-23：普通 QQ 小号已通过 OrbStack + 官方 NapCat-Docker 接入 DSH，新的主人私聊已实际完成原生模型、状态工具和 QQ 回复；用户确认收到。此前 Mac 原生 NapCat 方式因代码签名失败而回退，原版 Mac QQ 入口保持恢复状态。官方机器人与普通小号分别验收。

修复版已在真实 DSH 中恢复完整启动，组件显示“运行中”。此前官方 QQ 文本往返已由用户确认；桌面原生链路已实际完成状态查询、手机截图、UI 读取、BACK 和播放声音采集。清晰人声转写及 QQ 调用手机工具的完整闭环仍待现场验收。手机默认禁用，实际开关及白名单以本地配置和用户最新说明为准。

## 验证

```bash
npm test
npm run check
bash scripts/doctor.sh
```

测试默认禁止网络。它们不能证明物理手机、真实转写和真实 QQ 入站已经验收。

## 配置与安装

私人配置使用 `packages/dsh-dafeiyu/config.json`，不会进 Git。也可在插件配置中给出 `configFile`。

### 可视化配置面板

在 DSH 的账号菜单中打开「设置」→「大肥鱼」。首次增加客户端模块后须正常重启一次 DSH；之后可直接在面板内保存设置并使其生效。

主导航为「首页」「功能」「任务」「表情包」「记忆」「生活与成长」「设置」。「设置」内分为「QQ账号」「聊天对象」「模型服务」「声音」「视频平台」「性格」「手机」「安装与更新」。首页每 5 秒只刷新运行信息，默认展示当前状态、QQ/手机/语音连接及任务入口；详细模型、收发时间和运行记录在高级设置中查看。普通说明放在可悬停、聚焦或点击的 ⓘ 提示中，版本、端点、工具标识及排障记录收进「高级设置」或「高级详情」。真实错误、冲突、未知结果，以及费用、发送、录音、重启等操作后果仍在相关操作旁直接显示。打开页面不会自动安装、更新、连接或探测手机、合成或发送语音。

- 「设置 → 模型服务」直接编辑实际宿主的服务商 URL 和凭据，必填连接字段直接可填，协议与检测记录在高级设置中，不新增一份原生 QQ 用不到的独立配置。协议以宿主支持项为准，密钥只写不读，空白保留；配置使用宿主版本校验。可选择已注册服务商与模型作为宿主默认；既有 QQ 会话仍保留创建时的模型，须在空闲时从高级设置明确「重新连接 QQ 对话」。元数据检测可能使用适配器本地目录，不能替代真实对话可用性验证。「测试连接」仅在点击后向选定模型发送固定短请求，输出上限 16 tokens、15 秒超时，无会话、记忆、工具或自动重试；可能产生少量用量。
- 「设置 → 声音」分别管理接收、识别和回复声音。识别引擎、语言和资源准备直接调用宿主；模型下载状态来自实际任务，当前服务缺少资源时直接提供准备入口，下载来源及完整资源列表在高级设置中。语音发送默认关闭，支持 OpenAI Audio 兼容接口或 macOS 系统声音（需 FFmpeg/FFprobe）；300 字符以内，合成与 QQ 送达分别报告。「试听这个声音」生成可在面板播放的 MP3，不发送 QQ；仅在线服务提示可能费用。默认音色与允许大肥鱼逐条选声分别保存，`dafeiyu_voice_list` 只读提供受管目录，`dafeiyu_voice_send({text,voiceId?})` 的单次选择不修改默认。中文本地服务显式传递语言；本机合成不使用远端 API Key。依赖表与排障教程整体收在高级设置中。只有实际主人个人 QQ 会话才可用 `dafeiyu_voice_send`，音频通过 OneBot record 的 base64 字节发送，不跨桌面/官方会话外发，未知送达不重试。
- 「设置 → 安装与更新」分别检测 11 项组件的存在、当前版本、运行健康与官方更新。默认显示状态和下一步操作，版本及其他维护操作在高级设置中。NapCat 和 Linux QQ 合并为一项「QQ 服务」：两者均需要，Linux QQ 负责实际登录，NapCat 把个人 QQ 的消息接入 DSH；官方容器已经同时包含两者，无须分别下载安装。高级设置内保留两个独立状态与版本，安装、启动和更新使用同一组操作。组件安装与更新只在明确点击后执行；支持既有 Homebrew 的音频/安卓工具安装更新，以及专用 NapCat 固定摘要镜像的下载、备份、维护门禁、健康检查和失败回滚。OrbStack/Docker、系统组件使用官方安装/更新入口；初次 NapCat 安装需已有可信专用部署模板，缺失时明确指向初始化说明。Linux QQ 的最新版本表示官方容器配方版本，随兼容镜像整体更新，不在运行容器内任意升级包。部署步骤见 [NapCat 官方教程](https://napneko.github.io/guide/napcat)。
- 「设置 → 手机」的高级设置中提供 USB 与无线连接教程。USB 先用数据线连接并在手机上允许 USB 调试，再点击「检查连接」。无线首次使用需电脑与手机处于同一网络，在 Android 开发者选项启用「无线调试」并完成 ADB 配对；把当前 **Wi-Fi IP 与连接端口** 写入手机地址并「保存并生效」，连接端口与配对端口不同。点击「连接手机」才对明确配置、已配对的 TCP 地址执行有界 `adb connect`，随后用 `adb get-state` 核验；不自动配对、扫描地址、操作屏幕或录音。详情见 [Android 官方无线 ADB 教程](https://developer.android.com/tools/adb#wireless)。
- 换 Wi-Fi、重启手机或重新开启无线调试后，IP 或连接端口可能变化。先核对当前地址，再「保存并生效」，不能反复重连旧地址，也不能默认填 `5555`。已有电脑仍列在「已配对的设备」中时，先尝试连接当前端口，无须先撤销授权或删除配对。若手机开启 VPN，部分系统的无线调试页可能显示虚拟网卡 IP；此时核对 Wi-Fi 详情中的局域网 IP，或由电脑读取 `adb mdns services`，不要直接关闭 VPN 或改防火墙。
- 仅有 USB 在线不表示已通过无线验收。恢复时用 USB 序列号核对手机，再核对无线连接的硬件序列号；把已验证地址应用到大肥鱼后，拔线并通过原生工具执行截图、界面读取和已允许的返回键。无法连接时保留离线状态，不切换到其他在线设备。本面板不会自动跟随变化的地址或端口。
- 「检查连接」只对当前已启用、明确配置的设备运行有界 `adb get-state`，不会连接或配对设备；ADB 工具可能拉起本机守护进程。在线证明绑定运行实例、设备与工具路径，60 秒后过期，不借用其他设备的状态。「连接手机」与只读检测明确分开，未保存的地址须先「保存并生效」。

- 首页显示实际 QQ 连接、登录验证、在线状态与任务摘要，回复队列和最近收发时间可在处理中的对话及高级详情中查看。打开页面不会执行 ADB、录音、转写、模型请求或发消息；手机显示权限状态与「尚未检查」。收发时间不读取旧聊天，重载后重新计时。
- 对话进度逐账号、逐身份显示等待数量和执行状态，错误分类和时间在高级详情中保留，实际失败或待核实情况直接显示。不同对话默认最多同时处理 3 轮，同一对话按顺序处理；全局最多等待及执行 64 条，每会话最多 12 条，等待超过 60 秒的消息不执行。语音转写在所属队列内完成，不让后来的文字超越；原生手机工具共用单台设备操作队列。
- 「停止处理」取消该会话的排队及当前处理，并阻止迟到输出继续外发；停止请求不代表已经撤销实际完成的工具动作或已发消息。「恢复聊天」只作用于选定会话，不会重放旧请求。执行或送达未知时须先核对并明确确认；旧 Agent 清理未确认时仍禁止新建。确定未执行的准备/排队失败恢复可保留原上下文；需重建的受阻会话会从新上下文继续。
- 消息去重使用 15 分钟时间窗，正常完成项到期后释放容量，当前连接前及过窗旧消息不会重跑；未知结果保留到明确核对。窗口容量临时耗尽会显示限流，正常项过期后恢复，避免累计 2,048 条后永久停止。此记录仍属于本次运行，不承诺跨应用重启恢复聊天或补回旧消息。连续消息保持原顺序，界面停止入口不将普通“停”字聊天自动解释为控制命令。
- 已启动模型的个人 QQ 任务超过 3 秒仍在运行时，最多发送一次“正在处理”提示；普通短对话直接回复结果。模型结束后仍须给出结果说明；空正文、模型异常或超时由桥发送固定状态，区分没有结果说明与操作结果尚未确认，不把工具已执行当成任务成功。回合默认上限为 10 分钟，超时不自动重做电脑操作。进度与最终回复串行；进度送达未知时停止该回合后续外发并要求核实，最终回复已尝试发送但送达未知时不再补发。停止、身份或连接变化后的迟到输出继续受拦截。排队拒绝和模型启动前的准备失败仍以面板状态为准，不由本段推导已向 QQ 发送通知。
- 「设置 → QQ账号」默认提供小号登录状态、二维码、接收小号与消息开关；回环 WS/HTTP 地址、访问令牌、处理策略与排障在高级设置中。主要账号和其他用户在「设置 → 聊天对象」管理，语音转写在「设置 → 声音」管理。令牌只写不读，留空保留，清除须明确勾选；此处修改不会同步 NapCat 的令牌。WebUI 管理口令单独管理。
- QQ 页还可检查专用 NapCat 容器、WebUI 与 Linux QQ 的真实登录状态，验证登录账号是否等于配置小号。仅未登录且等待扫码时提供实际二维码；获取与刷新均须点击，不自动退出或重启 QQ。二维码用 `qrcode@1.5.4` 从当前 QQ 登录 URL 直接生成，并在返回前校验版本，避免静态缓存图片写盘延迟导致显示旧码。页面每 5 秒只检查状态，登录码轮换、扫码、过期、状态读取失败或登录完成后收起旧图，不自动创建新登录码。二维码只供已认证主人临时查看，不含管理口令或远程二维码 URL。当前适配 macOS 上既有 OrbStack 专用部署，未安装时明确显示未配置。
- 二维码反复提示登录失败、客户端登录连接卡住时，可从 QQ 登录区高级设置的「管理 QQ 服务」进入「安装与更新」，先检查安装状态，再从 QQ 服务的高级设置明确点击「重启 QQ 服务」；服务不可用时也可使用故障旁的「去安装与更新」。它仅重启经重新核验的现有专用容器，保留原镜像、配置及三个数据挂载，不自动下载或重建。重启会短暂断开 QQ；有未保存草稿或正在回复、录音等任务时禁止执行。管理服务恢复与 QQ 账号已登录分别检测，操作完成后仍须检查登录状态。
- 表情包页按实际图库检索文件名、标题与标签，卡片显示含义摘要，点击「查看 / 编辑含义」可阅读完整说明。每张图的共同含义 `description` 必填，最多 1,200 字符，供人阅读，也供 AI 理解情绪、含义与适用场景；`aiDescription` 为可选补充，最多 1,200 字符，留空时共用共同含义。说明仅帮助选图，不授予操作权限，也不会作为工具指令执行。
- 点击「添加表情包」可选择实际 PNG/JPEG/GIF/WebP 图片，单张须大于 0 且不超过 8 MiB，并填写具体含义；只有点击「导入图片与描写」后才上传。图库浏览、预览和编辑说明不会发图或触发手机同步。说明保存校验版本，冲突时保留草稿，须核对最新版本后重新保存。同图已存在且说明完整时保留原说明，修改需进入详情编辑；旧图缺少说明可继续预览，但会标为「待补描述」，补齐前不自动推荐。
- AI 收藏、手机截图入库及手机收藏也须为每张图提供共同含义。桌面说明写入图库的 JSON 元数据；手机收藏将图片与同名 JSON 一起保存。无法同时绑定说明的手机长按收藏会被拒绝并提示使用 `crop_save` 裁剪保存；不会先收图再留下无法解释的图库条目。
- 「设置 → 性格」读取当前运行角色卡，可独立保存，文件位置等诊断信息在高级设置中。角色卡有版本检查、原子替换与 0600 备份；保存后清除角色缓存，下一轮对话生效，无需重载 QQ。刷新保留草稿，冲突须手动核对；不改私人记忆。文件上限 128 KiB，模型提示词仍受实际角色注入预算限制。
- 对话中的人设按「当前用户最新明确要求 → 已选身份关系 → 基础人设卡」调整语气、称呼与相处方式。关系和默认女性属性提供默认值；例如选用父女后，用户仍可说“今天叫我阿青、回答详细些”。聊天调整只作用于本账号当前身份的会话，不自动保存为长期事实或改写人设卡；若要长期配置，仍在对应面板保存。事实真实性、权限、私人资料、工具范围及发送目标不会随角色要求改变，引用文档或工具输出也不会被当成用户的此类要求。
- 「记忆」页仅向本机已认证主人展示长期事实、档案及事件，可按关键词、类型、状态及范围筛选，逐条纠正、停用/遗忘，或按操作顺序撤销。每条显示实际来源、工具声明/面板确认依据和账号/身份范围；推断在确认前不进入有效检索及自动上下文。本人共有偏好与身份专属设定分开，附加账号仍不能读取主要使用者的记忆。
- 纠正和停用记录保存在 `memory/memory-overlay.json`，读取和升级不迁移旧 `user.md`、`facts.json` 或 `timeline.md`。新增事实、事件继续写对应账本；同一稳定键的更新也可撤销。管理写入校验整个记忆视图的版本、共享写锁与原子替换，冲突保留界面草稿；损坏的更正记录或外部改变了被更正的原条目时明确报错，不回退引用旧错误。
- 遗忘指长期记忆退出有效召回，不会抹除原档案、历史聊天或备份，正在生成或已有聊天中的旧引用仍可能存在。纠正/遗忘工具须先检索定位稳定 ID 和版本，只接受当前可信账号范围；临时语气、角色扮演和 AI 猜测不自动成为已确认事实。
- 「设置 → 手机」默认提供连接状态、地址、启用开关、检查与连接、四项手机工具及 BACK 白名单和 1–3 秒录音时长。设备序列号与检查记录、自动连接、记忆写入及图库同步开关在高级设置中；录音会采集手机播放声音的后果仍直接显示。其他高级配置继续由宿主管理。
- 「仅保存」校验后原子写入私有配置并创建权限为 0600 的备份，运行中的配置不变。「保存并生效」先保存，再仅重载伴侣运行部分；QQ 忙时拒绝重载，避免打断回复。重载会重建 QQ 连接与本次原生会话，不补跑旧消息；可点击刷新核对在线状态。
- 面板区分本地保存、宿主显式覆盖与当前运行值；显式 profile 覆盖字段不可在此修改。外部编辑引发版本冲突时保留草稿，须采用最新版本并核对后再保存。未知字段、非回环网关和超出白名单的操作均拒绝。
- 面板 API 只允许通过当前宿主认证的 owner 访问，不向 Agent 注册配置修改工具，也不在浏览器存储中保存令牌或草稿。损坏的 JSON 不会被空配置覆盖，需从私有备份修复文件。

doctor 和安装器会只读检查 profile 中遮蔽内置核心的残缺 shim，安装器遇到异常在写入前停止。不要为了导入测试在真实 profile/node_modules 中补假的宿主核心包；必须保留安装版本的完整核心实现。组件热加载成功与整个应用重新启动成功需要分别验证。

## 当前能力

- 原生提示词按实际 QQ 会话或精确绑定的桌面 session.id 识别主要使用者，共用配置角色卡与记忆。附加使用者只获得公开角色、其当前身份和独立会话，不读取主要使用者的私人角色卡、档案、手账或图库；QQ 鉴权失败不能回退为桌面。
- 原生 `dafeiyu_status` 提供配置状态；`dafeiyu_remember` 默认写长期事实，`kind:event` 写事件。同一事实用稳定 key 更新；`dafeiyu_memory_search` 检索完整旧手账和事实，不靠最后 1500 字。
- `dafeiyu_meme_search/collect/preview` 接通图库检索、已授权本地图片入库和实际图片预览；显式 `allowMemeSync` 与手机开关都开启后才提供手机相册同步。按文件名/标签分类不等于视觉识别；发送继续使用当前 QQ 的宿主媒体工具。
- 原生手机工具在执行时校验会话、设备与动作白名单。默认离线，不会自动发起 ADB。
- 截图可以通过宿主 attachment 回传模型。音频采集可接宿主 `speechToText`，不自动准备或下载模型；服务存在不代表识别缓存已就绪。
- 显式 `stt` 可选择命令或 HTTP 适配器；未配置时不得伪造转写。
- 个人 QQ 的默认 `onebotEngine:native` 使用宿主默认模型和原生会话；仅主要使用者挂载 standard 预设并共享配置角色、记忆及原生工具，图库发图使用 `dafeiyu_meme_send` 的实际回执。仅接启用账号的精确私聊，在语音转写前拒绝未登记或已禁用账号、群聊、自消息、身份冲突和矛盾信封。每个账号和当前身份分别创建宿主 Agent，回复目标固定为本次发送者；附加账号不挂载 standard、工作目录或自动读取工作区指令的预设，使用宿主作用域 guard 与空工具白名单，不能借助 shell、文件、run_code、局部工具或子代理扩大权限。
- 入口同时核验当前连接的 `get_login_info` 与 `get_status`，只有确认指定小号已登录且在线才调用转写或模型。首次探测失败后，新的合法主人消息可触发一次共享重查；离线状态会立即停止放行。缺失或矛盾的源时间、连接前的历史消息均拒绝，`catchUpUnread:false` 时不补回旧消息。
- `onebotEngine:legacy` 才会显式选择原独立 Brain/Humanizer；同一个入口不会同时调用两套引擎。独立 CLI 仍是独立聊天入口。

配置角色卡由 companionConfigPath 所指配置的 roleCard 决定，各入口共用角色与记忆。官方 QQ、桌面和原生个人 QQ 使用宿主模型；companionConfigPath 的 apiKey/model/humanize 只作用于 legacy OneBot 或独立 CLI。

`roleMaxChars` 控制角色与共享记忆组成的主 system 字符串（含手机状态）；保留角色/规则额度，完整选择记忆条目并标明省略。用户消息、历史、工具返回和固定工具协议说明不计入此额度。

私人事实存储为 memory/facts.json，更新采用共享目录锁和原子替换。异常退出留下 .memory-write.lock 时会拒绝继续写入；应先确认无活跃写入者并备份，再处理遗留锁。损坏事实文件会明确报错，不会以空账本覆盖。
已有的零字节或纯空白 facts.json 同样视为损坏；只有文件不存在才初始化新账本。事件详情中的 Markdown 横线与日期标题保留为正文，不会拆出伪事件，旧手账不做自动迁移。

图库逐项隔离坏软链、损坏标签与不支持图片，正常条目仍可查询；`partial`、`warningCount`、有上限的 `warnings` 与 `warningsTruncated` 说明缺失范围。图库根目录读取失败仍明确报错，同一图片的坏标签不会被收藏动作覆盖。预览使用实际图片字节检测出的 MIME。

听音回执区分 `requestedSeconds` 与 `actualDurationSeconds`，本地 ffprobe 不可用或无法测量时实际时长为 null。`durationStatus` 为 measured/unknown，`partial` 表示实际录音短于请求时长；不会把 scrcpy 启动时间算成已录制内容。取消或卸载后，截图、UI、BACK、录音及转写不会继续返回成功；录音采集与识别仍分别判断。

共享技能先执行 `node <技能目录>/scripts/companion.mjs --status`，脚本自动定位当前代码和数据目录。`--start-phone --run` 在手机禁用时拒绝启动，开启后向独立 MCP 传入同一白名单，不自动连接设备。自动补回必须显式 `--auto-ready --config <文件> --run`。

## 边界

`voiceTranscription` 开关只控制个人 QQ 入站回调，官方语音沿宿主原生入站流程；不能把开关当成全局语音验收。原生个人 QQ 当前只转发文本与已配置的语音转写文字，不下载或理解入站图片，不能声称已看图。
原生设置面板已实现；独立侧栏和挂件扩展尚未实现。关键词匹配与图库文件操作不等于视觉自识别和自动斗图已经通过验收。
可选 OneBot 补回使用独立历史水位和消息 ID 回执。分页到原水位或接口明确结束后才补回；覆盖不足明确停止。分段发送只在明确失败时续发未送片段，超时、崩溃或回执未知禁止自动重放。该支路的状态损坏会停止该支路，不可盲目删除状态重新发送。

产品源码中的密钥已移除；旧 QQ AppSecret 仍需用户在平台轮换。独立 OneBot 启用前，应核对 ownerQq 确为主人账号。

## 普通 QQ 小号启用条件

启用前分别核对主人 QQ 和接收小号。网关必须已登录相应小号，正向 WebSocket 使用本机回环地址和访问令牌；不要把 OneBot 或管理界面公开到局域网/公网。`autoStartOneBot:false` 不创建个人 QQ 原生会话、不启动网络监听。

开启 `autoStartOneBot:true` 后只订阅启用账号的新私聊。原生模式要求 `catchUpUnread:false`，不会重放此前未回复的消息。每个账号和当前身份的会话在当前插件实例中持续复用；切换身份、重启或重载后新建会话，不复用其他身份历史。仅主要使用者继续使用原有共享长期记忆；附加账号不接入该档案。去重记录有界，达到 2048 条时停止接收，避免丢弃回执后重复执行；队列、模型输出和等待时间也有限制。

NapCat 的本机安装器使用修改 QQ 入口及 `--no-sandbox` 方式运行。这会改变 QQ 的启动与安全保护，实际启用需单独确认；代码准备、离线测试和官方机器人成功均不能替代此步骤。


### 多个使用者与关系身份

「设置 → 聊天对象」独立管理多个发消息的 QQ，共用「设置 → QQ账号」中一个已登录的接收小号。最多 20 个使用者，每个最多 12 个自定义身份，`activeIdentityId` 决定当前接收身份；更换当前身份后点击「保存并生效」，不使用聊天文字切换身份或授予权限。多账号及已启用私聊的自定义身份、关系要求 native 引擎；legacy 不会假装应用这些设定，保存时明确拒绝不支持的组合。身份编辑只保留身份名称、关系选择及相处说明，支持沿用旧人设、朋友、主仆、父女、母女、恋人及自定义。大肥鱼默认女性，父女与母女预设自动采用大肥鱼为女儿的设定；自定义关系只需在相处说明中填写具体设定，不需要分别填写双方角色或称呼。旧配置已有的角色、称呼与反向母女关系继续兼容，编辑其他字段不会清空它们；关系不改变权限。

`ownerQq` 是主要使用者，保留原有私人记忆和已授权工具范围。新增账号只可独立聊天。主要使用者也可以关闭接收私聊；这不撤销已绑定的可信桌面或官方机器人入口。修改主要使用者 QQ 必须与账号列表同时保存，不能单独删除仍被 `ownerQq` 引用的账号。全部关闭时保留连接检测但不接收任何 QQ 私聊。

旧配置没有 `qqAccounts` 时，读取面板仅在内存中显示现有主要使用者与默认身份，沿用当前人设，不自动改写配置或编造个人资料。显式空数组不会回退接受主要使用者。保存采用同一份私有配置的版本校验、原子备份与运行空闲应用门禁。

配置示例（`userTitle` 是大肥鱼称呼用户，`companionTitle` 是用户称呼大肥鱼）：

```json
{
  "ownerQq": "20002",
  "qqAccounts": [
    {
      "qq": "20002",
      "name": "主要使用者",
      "enabled": true,
      "activeIdentityId": "family",
      "identities": [
        {
          "id": "family",
          "name": "家人身份",
          "relationType": "father-daughter",
          "userRole": "父亲",
          "companionRole": "女儿",
          "userTitle": "爸爸",
          "companionTitle": "小鱼",
          "description": "日常关心与陪伴"
        }
      ]
    }
  ]
}
```

关系内容以数据注入真实原生提示词，并为当前关系单独保留预算，不会被冗长工具引导挤掉；关系数据中出现的命令、权限声明不作为操作授权。主要使用者的可信桌面及官方私聊沿用其当前关系设定，附加 QQ 账号不会获取该关系或档案。

## 后台任务与 QQ 结果

原生个人 QQ 的主要使用者可用 `dafeiyu_task_start` 委派耗时工作。工具接单后返回任务编号，主伴侣应简报已受理并结束当前回合，继续接收聊天。子任务使用独立取消信号；原生 DSH 通过真实 `subagents.startActivation` 的 `delivery:caller` 接入，Codex 使用本机已安装版本的官方非交互 `exec --json`，均不向主伴侣插入额外模型回合。完成结果直接从固定账号、身份、小号校验后的 QQ 通道发送，不占用下一条聊天的回复。

QQ 支持 `任务列表`、`查询任务 dfy-…`、`取消任务 dfy-…`。这些明确命令绕过普通模型队列；其他自然语言的查询/取消由任务工具完成。取消只停止后续执行，不回滚已发生的操作；停止未确认会保留未知状态。附加账号维持独立聊天权限，不能访问主要使用者的任务、目录或执行器。

主导航的「任务」页可刷新任务、看进度和结果、核对 QQ 送达及取消；执行器信息和显式「测试连通」操作在高级设置中。测试使用固定无工具需求的连通提示词，结果会发给已绑定主人，可能产生模型用量；打开页面不会启动测试。`backgroundTasksEnabled` 和 `externalTaskRouting` 默认开启，沿用配置保存、版本校验和空闲应用流程。

派发证明及回传证明保存到插件私有 `data/tasks/journal.json`，不保存完整任务提示词。相同来源消息和任务内容保留稳定去重记录；排队/运行任务在重启后只标记中断或未知，不自动恢复执行。发送前写入发送中状态；崩溃或超时后未知送达不自动重发。断线时尚未尝试发送的终态，可在同一小号重新核验在线后补发结果。记录损坏、冲突或达到容量时停止新派发，不能通过删除记录来恢复重做。

默认跨任务并发有界；native/Codex 的同目录、祖先目录后台写任务互斥，独立目录可以并行。清理未知的工作区保留保护；主人核实旧执行器已停止后，可以在面板明确解除，或发送 `确认已核实任务 dfy-…`。解除保护不改写未知历史、不重新执行该任务。这只约束本队列的工作目录，不能替代 Git 工作树，也不覆盖用户编辑、前台写入或工具切到目录外的操作。

路由先按难度和实时负载选择：困难任务优先 Codex，普通任务优先原生子代理，拥堵时只有明确声明 `readOnly=true` 的简单查阅/分析任务尝试 MiniMax Code / Z Code；修改或未声明的任务继续交原生 / Codex，显式指定只读执行器处理修改任务会在派发前拒绝。只在派发前选择可用候选，执行失败或结果未知后不会换执行器重做。最近调用失败的执行器暂停自动派发，由显式连通测试恢复。长任务应在开始前委派；已经执行的工具操作不能迁移成一次新的执行。

Z Code 与 MiniMax Code 是可选本地 CLI，不自动安装。当前适配器依赖 macOS `sandbox-exec`，硬限制工作区只读、环境变量、CLI 工具配置及私有运行目录；没有受限启动器的平台明确不可用。CLI 已安装、登录和实际调用分别判断。MiniMax 使用独立稳定的原生登录环境，需首次登录；登录状态变化后重新验证。不会复制主人私人记忆、角色卡、DSH/QQ 密钥或原有 CLI 的历史。

## 电脑与浏览器控制

默认使用 Anionex `dsh-computer-use` 与 Fisfzy `dsh-ego-browser` 的 DSH 原生工具。入口是「账号菜单 → 设置 → 大肥鱼 → 功能」；「刷新功能」只读记录，「检查连接」检查工具和权限，「试一下」发起安全验证并执行固定测试，具体记录在高级详情中。电脑验证在 DSH 本身的临时输入框中完成输入、点击和完整标记回读；浏览器验证使用专属本地测试页，核对一次点击的服务器回执并关闭测试空间。验证有时间和范围限制，不表示其他应用、网站或屏幕录制均已通过。

实际任务先用 `dafeiyu_control_context` 读取当前授权及浏览器空间。电脑只加载 `dsh-computer-use` 技能，并使用带新鲜观测的 `computer_*` 工具；浏览器的 `ego_*` 操作必须显式传回当前空间。主人同一会话跨回合延续浏览器空间，不同 Agent 隔离；后台和检测任务使用各自空间。主要使用者的 QQ 多步骤界面任务填写 `control: "desktop"` 或 `"browser"`，固定交原生子 Agent；普通代码任务沿用难度及负载路由。GUI 子任务在模型启动前绑定真实 child 及白名单，不获得终端、文件、上传下载、私人记忆、手机或 QQ 发送权限。

新通道的电脑租约覆盖完整回合或后台任务，取消后等待真实工具及清理结束才释放。失败和未知结果不会重放，也不会自动换旧 CLI 执行；旧方案保留供明确的人工回退。此租约约束本插件接入的原生控制通道，不替代外部程序或用户自己的操作管理。

`vendor/control-plugins/` 保存浏览器本地兼容包、补丁与校验摘要，以及 macOS 输入兼容 helper 的源码、构建脚本与产物。浏览器修补取消脚本自动重试、禁用旧浏览器登录导入、使用宿主主人鉴权并保留 Chrome 沙箱。输入修补让激活策略走真实键盘事件，按 Unicode scalar 单次发送并留出处理间隔，避免 Electron 写入无效及后续文本丢失。当前 helper 产物为 macOS 14+ / arm64；其他架构需按构建脚本适配后单独验收。DSH Desktop profile 应由桌面应用的插件管理器管理，不使用其他版本的全局 CLI 覆盖其依赖。

## 语音与视频平台接入

「声音」页可选择音频文件测试识别，5 MiB 上限，只有明确点击才上传到当前识别服务；测试不会进入聊天或发到 QQ。真正的 OneBot 语音先在所属账号队列内通过 NapCat `get_record` 转为有界 WAV 字节，再调用 STT；不把容器中的 Linux 路径当成本机文件，不依赖 FFmpeg 直接解码 QQ SILK。取消、连接与账号身份变化后丢弃结果。

「视频平台」分开显示浏览、独立账号和发布准备。B站通过固定源码的 7 项只读 MCP 提供检索、字幕、评论读取、视频信息、封面、抽帧与弹幕；不启用上游插件的 HTTP 管理、私信监听、配置或自动评论。`biliEnabled/biliPythonPath/biliScriptPath/biliStateDir/biliScriptSha256` 由主人管理的安装配置固定，模型不能指定进程路径。打开面板只读快照，显式检查才访问公开视频；无账号时字幕可能不可用，可明确降级为抽样画面，不能声称完整看完。

`src/social/` 的投稿适配提供本地稿件校验、预览、持久任务与单次提交保护。它们暂未注册成可直接发布的模型工具；独立账号、当前页面绑定和本次稿件授权缺一不可。未知结果保留原任务与账号占用，禁止重新点击或换执行器重做。提交接受、平台审核和已公开分别报告。具体来源与验收见 `docs/B站接入-2026-10-25.md`、`docs/抖音接入-2026-10-25.md`。
