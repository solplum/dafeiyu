## 本轮行为

对大肥鱼已核验归属的原生模型请求，在真实 provider 启动及 Token `started` 之前检查整次请求。计量包含独立 system、全部历史消息、工具结果、reasoning/replay 数据、当前和历史工具定义、stop 等实际宿主字段，并留出实际 maxTokens；缺失时仅使用该精确模型返回的默认输出上限。读取当前适配器声明的 contextWindow，并与同路由已绑定窗口取较小值，不猜模型容量。

这是一套保守准入估算，按 UTF8 JSON 字节、结构开销和宿主附件投影计量，**不是精确分词、真实消耗或额度扣款**。75% 起给后续上下文添加压缩提醒，保留原 Billion Context 压缩链；预计输入加输出超过 90% 保护线时暂停。另有 2MiB、4096 条消息、16384 个块、512 个工具、100000 个节点及 32 层深度的本地有界限制。图片必须有宿主路由价格投影，文件必须有真实 fileRequestText 投影；未知结构、附件投影、模型容量或输出预留无法确认时暂停，不能当作零输入放行。模型元数据查询有 5 秒上限，取消和卸载会阻止后续派发。

只守护已由现有 Token 归属链核验的请求，账号、身份、用户任务、自主活动及真实子 Agent 的既有权限不变。无关宿主会话不进入该门禁。外部 CLI、legacy 独立 Brain 不在这轮原生完整请求保护的验收范围。

## 压缩故障与继续聊天

- 真实 `tools/result` 中受管压缩工具失败、原生 compaction 失败/中止，以及宿主标准 finish 中的 `CONTEXT_WINDOW_EXCEEDED` 会锁定对应会话。不会根据原始错误文本或模型声称构造诊断，也不反复重试模型。
- QQ 只向原已核验目标发固定的文字状态提示。暂停排空原队列并保留去重证明和旧 Agent；不宣称已经发生的操作被撤销，也不把本次请求未发出推成整回合未执行。之前模型、工具或送达结果未知的确认门槛继续保留。
- “恢复聊天”会只读检查当前完整上下文，检查许可绑定真实 Agent、session.seq 和当前故障对象；并发变化拒绝清除。未来模型调用仍再次检查实际冻结请求。
- 新增明确的“用新会话接收后续消息”：只对上下文暂停开放，确认旧执行器清理完成后才结束当前映射；下一条新消息才创建新 UUID。**不复制旧消息、不重跑原请求、不自动继续旧任务、不删除私人记忆。** 旧会话沿宿主原有 persistence close/detach 流程处理，不调用删除历史的 API。
- 实际界面提交当前 controlVersion，旧版本不能确认后来出现的新失败。旧按钮 handler 不能绕过新草稿、应用状态或新版未知结果确认；唯一暂停会话换新后，其成功说明在卡片卸载后仍保留。

## 为什么保留原始请求保护线

当前实际安装的 Billion Context 为 0.1.206，负责 QQ 和普通宿主模型链路。源码确认：它在部分代理不可用路径会发送普通未压缩请求；没有公开的 failClosed/proxyOnly 设置或正式的回退拒绝注册接口。只读 status/snapshot 也不能完整重建下一次实际出站请求。不能根据上一次压缩后的 Token 数，放行这一次过大的原文。

Billion 的摘要在代理侧，宿主原始历史可能不缩小。因此此轮原始请求保护在极长、但代理压缩正常的会话中也可能较早暂停；代理自己的压缩成功不保证普通恢复检查通过。明确换新会话是可用的继续方式。这是防止溢出的保守保护，**不是无限上下文或已实现新的自动摘要引擎**。没有修改第三方插件、宿主核心、用户压缩配置或私有全局状态，也没有强行启用与 Billion 冲突的 stock compaction。

## Token 一致性

本地拒绝发生在 Token `started` 之前，不生成模型请求、用量、未知消费或自主预留。等待元数据后会再次核验归属与取消；已开始的真实 main/title 用量仍按现有规则结算，取消或失败不抹掉已报告消耗。此前已执行步骤和未知清理仍有独立证明，不因上下文暂停或换新会话降级。

另确认 Billion 的 authoredCompaction 可以本地生成 checkpoint，同时返回按字节估算的合成 usage。这个数字不能当成真实模型消耗；可选策略 marker 缺失也不能反证 usage 来自真实上游。当前受管 `purpose=compaction` 回执在来源无法验证时统一保留为未计量，不猜 0、不扣真实消耗。正常结束但来源未确认显示保护待核对，不能据此称“压缩失败”；错误、中止或截断才归为压缩未完成。真实 compaction 计量来源仍需后续宿主联调补证。
