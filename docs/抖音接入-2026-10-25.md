# 抖音第一阶段接入 · 2026-10-25

已能在没有抖音账号时检查本地视频、生成可核对的稿件预览；没有账号时明确拒绝上传和发布。本轮没有登录抖音、浏览真实账号、上传素材或发布内容。

投稿适配源码现已纳入本项目 `src/social/`，尚未注册为可直接发布的模型工具。独立账号和创作者页面尚未提供，不能宣称线上发布或审核回查通过。只读浏览工具和面板检查已另行接入，详见《抖音只读浏览-2026-10-25.md》。

## 已实现

| 入口 | 实际行为 |
| --- | --- |
| `prepare(input)` | 读取指定本地视频/封面，计算 SHA-256；用本机 ffprobe 核对视频轨道、时长和尺寸；校验标题、描述、话题、AI 声明；生成持久稿件编号和批准摘要。不会启动浏览器。 |
| `preview(id)` | 读取本地稿件与日志；没有上传、点击、模型调用或网络请求。 |
| `upload(id, approvalDigest)` | 必须绑定指定账号、取得本稿件授权，并且浏览器当前账号一致。上传前再次核对媒体哈希。上传后精确回读编辑页，停在尚未发布。 |
| `submit(id, approvalDigest)` | 再次核对账号、文件、编辑页内容和草稿标识；持久写入 dispatching 后只尝试一次发布。只有响应中的精确作品 ID 能进入 submitted。 |
| `query(id)` | 使用本次响应中的作品 ID 读取同账号作品管理记录，分别报告审核中、公开、拒绝、私密、删除。不把“审核中”写成“已公开”。 |

准备稿件可包含封面与最多五个话题；当前最小浏览器驱动对封面/话题控件尚未实测，遇到这些选项会拒绝上传，不会悄悄丢掉用户选择。AI 声明也必须在当前创作者页实际核对，不会替用户默认声明 AI 内容。

## 单次提交与失败恢复

状态顺序为 `prepared → uploading → ready → dispatching → submitted → verified`。

- 相同账号、视频/封面哈希及完整元信息产生同一个稿件编号。再次 prepare 读取原状态，不会将已提交或未知状态重置成可提交。
- 每个账号有进程间排他锁，覆盖上传、发布与回查。未知结果保留账号锁；崩溃锁不按时间自动过期，不能换个标题绕开未知执行。
- 上传中或提交中遇到超时、断连、进程中断、取消、缺少精确回执，均保留 unknown。页面跳转和“成功”提示不足以确认发布。
- 当前安装的受管 Ego 已移除整段脚本的自动重跑。上传和发布脚本内部仍以 `openSync(..., 'wx', 0600)` 和 `fsync` 持久创建各自的一次性 claim，即使传输层意外重放，也会在上传或点击前拒绝。claim 永不自动删除。
- unknown 不自动重试、不切换执行器、不重新点击。需要先由用户核对作品管理与旧浏览器进程；当前 staging 没有提供“强制重新发布”入口。没有精确作品编号时，query 不按同名标题猜测原作品。

这份日志模块按平台/账号设计，可供 B站后续复用。文件包含媒体路径与稿件文本，目录为 0700、文件为 0600，不写 Cookie、账号密码或浏览器原始日志。

## 当前浏览器接入边界

`EgoDouyinDriver` 接收受信任的 `runScript` 调用器、专用任务空间、精确标签页 targetId，以及真实账号下核验的页面绑定。它只接受 `https://creator.douyin.com`，每次动作与跳转后检查账号标识。

账号选择器、账号唯一属性、上传就绪标识、草稿 ID、发布按钮、作品管理行、审核状态映射与提交响应路径必须先在独立账号中观测。未设置 `bindings.verified=true` 或缺字段时立即拒绝，不启动浏览器。固定源码只证明它曾使用那些选择器，不能证明当前线上 DOM 未变；本次没有捏造未验证的抖音接口地址或审核状态数字。

`runScript` 由后续 DSH 接入层调用真实 `ego_script` 并只提取严格 sentinel 结构化结果。驱动兼容原生 `{ok,result}` 与调用器标准化的 `{ok,value}`，拒绝超时、取消、unknown、fallback、两份冲突结果或只有原始 stdout/stderr 的“成功”。它接收 `noRetry:true` 提示，安全性同时依赖脚本内持久 claim。

本地实测发现一个真实运行时限制：`waitForResponse` 在收到响应头后释放 Network 监听，随即调用 `Response.json()` 会报 `No resource with given identifier found`。驱动已改为在点击前对核验过的**精确投稿端点**安装一次 fetch/XHR 响应捕获，复制原请求的响应（最多 256 KiB），同时核对原生响应 URL/status；读取后恢复页面钩子。不会重新请求投稿端点、重新点击或从页面提示猜作品编号。接口 `pattern` 必须是当前已观测的完整 HTTPS URL，不能把 glob/模糊子串当成精确回执。页面跳转或正文不可用仍进入 unknown，不自动恢复发布。

本项目已新增独立只读浏览模块及真实 owner 面板检查，经原生 ToolRuntime、当前任务和取消门禁执行。本轮公开页面遇到登录或人工验证，未验收实际视频采样；没有自动推荐流、点赞、评论、私信、关注或转发逻辑。后续自主活动与后台浏览需要另外按当前域名、账号和任务授权接线。

## 本地运行与证据

以下命令只检查本地稿件，不会上号或上传：

```bash
node staging/cli.mjs prepare /absolute/draft.json /absolute/private-journal
node staging/cli.mjs preview 稿件编号 /absolute/private-journal
node --test tests/douyin-publisher.test.mjs
```

稿件示例：

```json
{
  "video": "/absolute/video.mp4",
  "title": "作品标题",
  "description": "作品说明",
  "tags": [],
  "declaration": "ai-generated"
}
```

声明只接受 `none` / `ai-generated`，由真实内容决定。独立账号提供前可以省略 accountId；此时只能准备与预览。

实际离线验证使用 FFmpeg 在本机生成一个 1 秒蓝色视频，ffprobe 返回 320×240 / 1 秒，`prepare` 生成了 `state=prepared`、`accountId=null`、`uploaded=false`、`published=false`。可回读 `evidence/offline-prepare.json`，本地样片为 `evidence/local-preview.mp4`。

13 项隔离测试通过，覆盖缺账号拒绝、unknown 防重放、跨实例锁、元信息/媒体一致性、实际执行生成脚本两次仅一次上传/一次点击，以及真实 native 返回 envelope 的正反例。测试中的投稿行为均为替身，不能替代真实账号验收。

另已运行 `tests/ego-runtime-owned.mjs`：使用**已安装插件的真实 bundled runtime** 和本机 Chrome，在独立临时 profile/任务空间的自建 loopback HTML 页面完成文件输入、普通输入、contenteditable 输入、点击与精确 JSON 回读。fetch 与 XHR 两条路径各点击一次，服务器总计收到两次独立本地测试请求，任务空间关闭且专用浏览器已停止；没有访问抖音或任何账号。证据 `evidence/ego-runtime-api-live.json`；第一次复现的原生 Response.json 错误日志保留在 `evidence/ego-runtime-owned/run-OAuhee/`。该验证证明 API 与本地回执链路，不能证明抖音当前选择器、上传或投稿已通过。

## 独立账号到位后的验收

1. 用户完成独立抖音账号登录，在当前 Ego 专用空间读出唯一账号标识并确认归属，不复制日常浏览器 Cookie。
2. 对该账号实际观测页面字段及提交响应，记录经过核对的绑定；先验证只读作品管理回查与未发布草稿回读。
3. 用户核对一份明确稿件与目标账号后，上传至编辑页回读；再批准本次单次发布，捕获精确作品编号，并查询该作品审核状态。
4. 断线/超时只回查旧作品，不重放发布。完成真实证据后，才接入正式大肥鱼工具和消费者面板。
