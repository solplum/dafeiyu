## ⚠️ 录之前先读这一段：别碰现在这只

现在这套是**活着的**（她在线、桥接在跑、DSH 在跑）。录制会不停地点这个、重启那个 —— 一条原则：

> **正式那只全程不动。演示用一套"影子环境"。**

三条硬规矩：

1. **不重启正式桥接**。录制里所有"启动 / 重启"的画面，都在影子目录里做。
2. **不让两个桥接同时听 3000/3001**。两个桥接连同一个 SnowLuma = 你发一句话她回两条，消息还会互相抢。演示桥接只在"已经确认正式桥接停了"或者"用另一套端口"时启动。
3. **令牌不许进画面**。录制前把要出现的令牌先改成假的（比如 `demo-token-123456`），录完再改回去；或者录完剪辑打码。

**影子环境已经建好了（2026-10-14 建的，直接能用）：**

```
正式：  E:\SnowLuma        E:\qq-bridge         ← 全程不动
影子：  E:\SnowLuma-demo   D:\demo-bridge       ← 录视频用这个（已配好）
会话：  E:\demo-session                          ← 影子专用工作目录
```

| 项目 | 正式 | 影子 |
|---|---|---|
| SnowLuma WebUI | 5099 | **5199** |
| OneBot HTTP / WS | 3000 / 3001 | **3010 / 3011** |
| 桥接控制台 | 3100 | **3101** |

启动：双击 `E:\SnowLuma-demo\launcher.bat` → WebUI 5199 扫码 → 双击 `D:\demo-bridge\启动demo.bat`。
两个目录里各有一份 `录视频用-说明.md`，录之前扫一眼。

**唯一需要你自己确认的**：SnowLuma 钩的是 QQ 客户端，同机同时跑两个号需要 QQ 能多开。不能多开的话，影子环境只用来录"安装、配置、跑起来"的画面，"她回复你"那段用正式实例实拍（发消息不伤她）。

# 第 2 章 · QQ + SnowLuma（8:00）

**这一段的目标**：让 `http://127.0.0.1:3000` 能应答。

### 2.1 解压（1:00）

※ 解压到 `E:\SnowLuma`，镜头扫一遍目录：`launcher.bat` / `node.exe` / `config\` / `data\` / `logs\`

▣ 贴字：**她（QQ）说的话，都经过这个程序翻译**

### 2.2 装依赖（1:30）

```powershell
cd E:\SnowLuma
npm install
```

※ 关键：**先把 QQ 完全退掉**（托盘右键退出，不是最小化）

⚠️ 翻车点：QQ 没退 → 依赖装上了也注入不进去

### 2.3 启动 + 扫码（2:00）

1. 双击 `launcher.bat`
2. 浏览器开 `http://127.0.0.1:5099`
3. 用**她那个小号**的手机 QQ 扫码

→ 屏幕上：WebUI 显示她的头像、昵称、QQ 号，状态**在线**

⚠️ 翻车点：扫码后 QQ 客户端会自动重启一次（注入），**这是正常的**，别以为崩了

### 2.4 开两个口子（2:00）

WebUI 里：

| 开什么 | 端口 | 用途 |
|---|---|---|
| HTTP 服务 | `3000` | 发消息、查状态（记得勾 WebSocket 支持） |
| WS 服务 | `3001` | 收消息 —— **不开这个她就聋了** |

▣ 贴字：`3000 = 嘴　3001 = 耳朵`

设一个**访问令牌**，复制出来（画面里挡住）。

### 2.5 自检（1:30）

```powershell
$h = @{ Authorization = 'Bearer <你的令牌>' }
Invoke-RestMethod 'http://127.0.0.1:3000/get_status' -Method POST -Headers $h
```

→ 屏幕上：`online: true`

⚠️ 翻车点（重点讲）：**别用 `get_login_info` 判断活没活** —— 它掉线了也照样回你。判活只认 `get_status`。

# 第 3 章 · 桥接（8:00）

**这一段的目标**：日志里出现 `SnowLuma 已连接：ws://127.0.0.1:3001`

### 3.1 装（2:00）

※ 双击 `安装.bat`，五步走：

```
[1/5] 检查 Node.js / npm
[2/5] 下载 qq-bridge 解压
[3/5] npm install ← 最慢，3~5 分钟，画面停这里说一句"别关窗口"
[4/5] 生成 config.json
[5/5] 弹出记事本让你填
```

⚠️ 翻车点：npm 卡住 → 脚本会问你要不要换国内镜像（npmmirror），建议换

### 3.2 填三个地方（2:30）

```jsonc
{
  "ownerQQ": "★你的QQ号★",

  "allow": {
    "private": ["★她的QQ号★", "★你的QQ号★"],
    "groups": []
  },

  "snowluma": {
    "httpUrl": "http://127.0.0.1:3000",
    "wsUrl": "ws://127.0.0.1:3001",
    "accessToken": "★SnowLuma 里那串令牌★",   // ← 填这里！
    "homeDir": "E:\\SnowLuma"                  // ← 关键，见 3.3
  }
}
```

▣ 贴字（大号字，全片最重要的一张）：**令牌填 `snowluma.accessToken`，不是 `onebot.accessToken`**

⚠️ 翻车点：填错层级 = 一直连不上 = 她一句话都不回。这是新手第一大坑。

### 3.3 为什么第一次连接会"失败"（1:30）

※ 启动后故意让日志停在那一屏，一行为一行讲：

```
SnowLuma 首次连接未成功（将在后台自动重连并尝试自愈 WS token）: ...
SnowLuma 连接断开（code=1006），重连中…
   自愈完成：账号 ★她的QQ号★（close code=1006）
SnowLuma 已连接：ws://127.0.0.1:3001          ← 看到这行才算通
```

🎙 口播：

> "SnowLuma 的 HTTP 令牌和 WS 令牌是两个不同的值，配置文件里只能存一个，所以第一次连 WS 必然失败一次 —— 桥接会自己去 SnowLuma 的配置目录里把真正的 WS 令牌读出来，这一步叫'自愈'。**看到'首次连接未成功'不要慌，那不是错误，是流程。**"

⚠️ 翻车点：如果日志里是 **`token 自愈失败`** —— 100% 是 `snowluma.homeDir` 配错了。

### 3.4 启动顺序（1:00）

```
① DSH 先起来（43129 能开）
② SnowLuma 起来（WebUI 显示在线）
③ 桥接起来（日志出现「SnowLuma 已连接」）
④ QQ 里发一句话验证
```

▣ 贴字：`DSH → SnowLuma → 桥接`

# 第 5 章 · 角色卡：决定她像不像人（6:00）

**这是全片含金量最高的一章**，前面都是技术活，这一章是手艺活。

### 5.1 先立一个最高原则（1:00）

▣ 贴字：**先像个人，再谈人设。**

🎙 口播：

> "大部分人做 AI 女友失败，不是技术问题，是**写卡写歪了** —— 写了一堆'温柔善良可爱'，结果出来一个客服。"

### 5.2 六段结构（3:00）

※ 打开 `roles\小鲸鱼.md`（或者示例卡 `packages\companion\role.example.md`），一段段过：

| 段 | 写什么 | 反例（别这么写） |
|---|---|---|
| 一、你是谁 | 身份 + 对"你是 AI"这个事实的态度 | "你是一个乐于助人的 AI 助手" |
| 二、你怎么说话 | **短、碎、分条、口语、少问句** | "你说话温柔体贴、条理清晰" |
| 三、你的脾气 | 傲娇/毒舌/有主见/会拒绝 | "你永远耐心、永远积极" |
| 四、说话示例 | **给 5~10 组真实对话样例**（最重要的一段） | 只写形容词，不举例 |
| 五、边界 | 不跳戏、不透露设定、不编没做过的事 | 空着 |
| 六、记得的事 | 记忆怎么用、喊谁"宝宝"、什么话不能对外说 | 空着 |

▣ 贴字：**示例比形容词管用一百倍**

### 5.3 三个"立刻见效果"的写法（1:30）

1. **长度上限**：`默认一句话 1~15 字`
2. **不许每句都关心**：`不要每条以问句结尾，不要总结升华，不要免费建议`
3. **允许难听**：`被夸嘴硬，被指挥吐槽，被要求做不想做的事就说"不"`

🎙 口播：

> "很多人受不了这一条 —— 我让她可以怼我。因为**一个不敢怼你的 AI，你三天就腻了**。"

### 5.4 改完不用重启（0:30）

※ 改角色卡 → 下一轮唤醒就生效（画面：改一个字，然后立刻发消息验证）

# 第 6 章 · 第一次对话 + 人味参数（6:00）

### 6.1 第一次对话（1:30）

※ 拿大号给她的号发 `在吗`

→ 屏幕上：几秒到几十秒，她回你。**回了 = 整条链子通了。**

### 6.2 人味参数：对比实验（3:00）

※ 这一段做成 A/B 对比，视觉冲击最强：

| 参数 | 关掉的样子 | 打开的样子 |
|---|---|---|
| 分条 (`send.burstEnabled`) | 一大段话糊过来 | 拆成 2~4 条，间隔 1~3 秒 |
| 打字状态 (`typing.enabled`) | 秒回 | 先"正在输入…"，再出字 |
| 打字时长 (`msPerChar`) | 固定 | 按字数算，长句更久 |
| 唤醒与潜水 (`wake.*`) | 你发什么都秒回 | 有时在潜水，@她才醒 |
| 主动找你 (`proactive.*`) | 永远等你开口 | 隔一段时间主动冒一句 |

▣ 贴字：**这些参数才是"像人"的地方，不是模型多聪明**

⚠️ 翻车点：手感参数别一次调太满（比如每条都拖 10 秒），真人不会这样；从默认值开始，微调。

### 6.3 一个反面演示（1:30）

※ 故意把 `maxSendPerMinute` 调到 60、把延迟调 0 → 让她刷屏 → 观众自己感受"这就是机器人"

# 附录 B · 翻车预案（录到一半出问题怎么办）

| 情况 | 现场处理 |
|---|---|
| 下载慢/卡住 | 直接剪掉，画面贴"这里等 3 分钟"，别硬等 |
| 扫码失败 | 换手机热点；不行就切到提前录好的片段 |
| 依赖装不上 | 现场关掉 Watt Toolkit / 换淘宝镜像重跑 |
| 她就是不回 | 别在镜头前调试超过 1 分钟：切"故障排查"那一段（第 8.2 章）当正片用 |
